# ADR 0001：以 TypeScript 核心加 Julia 计算模块起步

- 状态：接受
- 日期：2026-10-05

## 决定

CW Station 采用 TypeScript/Node.js 作为台站控制、CLI、本地 API、日志协调和操作界面的主工程语言；Julia/MWORKS 作为独立的科学计算、信号处理、仿真和评估模块。首版采用模块化单体守护进程，计算模块通过版本化任务/结果协议调用。

## 原因

- TypeScript 适合共享契约、CLI、本地 Web 以及长期重构。
- 当前 MWORKS Syslab 已有 `TyRF`、`TySignalProcessing`、`TyDSPSystem`、`TyMathFFT`、`TyInstrumentControl`、`TyCommunication` 和 `TyPlot` 等可复用能力。
- Julia 的启动、编译和重计算延迟不应进入发射安全路径。
- 外部深度学习解码器保留原生运行环境，避免为统一语言重写已存在的算法。

## 边界

TypeScript 不等待 Julia 计算结果才能执行急停或处理发射安全事件。Julia 模块不得直接访问发射设备。任务、结果、算法版本和输入数据 hash 都要记录，确保回放可复现。

## 后果

项目需要维护两套运行时和一个跨语言协议。协议必须先版本化；算法包和 MWORKS 环境必须记录版本。只有当信号处理需求实际出现时，才增加 Julia 常驻服务或流式接口。
