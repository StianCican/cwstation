# ADR 0002：保留 unknown 结果，以独立核查记录解除阻止

- 状态：接受（用户同意推进，2026-10-05）
- 适用范围：Phase 0 FakeKeyer 离线实现

## 决定

保留执行的 unknown 结果，增加单独的核查记录与审计。核查声明包含操作人、理由和已确认停止，不表示原消息已成功发出或完成 QSO。只允许核查启动恢复时已有的 unknown；本进程新产生的 unknown 必须停机重启后处理。

解除与撤销旧批准、终止开放提案、generation 递增、更新阻止状态在同一事务提交。多条 unknown 须逐条核查。最后一条核查完成且不存在其他故障时，才允许重新创建并批准新提案。任何持久化故障仍禁止解除，重复请求不重复改变状态。

存储故障采用独立 `storage_fault` 字段，schema 4 显式迁移，禁止以 unknown 核查清除。记录故障时尝试单独持久化；数据库完全不可写时，只能保证本进程闩锁，后续恢复依赖已有执行记录及人工检查。旧库仅识别旧控制器生成的完整 unknown 阻止文案，无法分类的已有阻止保守迁移为故障。正常运行的解除逻辑不依赖文案匹配。

## 理由与限制

独立记录避免篡改未知的历史执行结果。重启要求使本进程 FakeKeyer 的迟到操作不能与解除后的新操作交错。同一 OS 用户的声明并不能证明真人参与或真实设备停止；真实设备核查步骤在 Phase 1 确定，不直接复用离线声明作为物理停发证明。
