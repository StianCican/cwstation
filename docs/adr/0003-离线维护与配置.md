# ADR 0003：配置与离线存储维护

日期：2026-10-05。状态：已接受设计，实现与验收状态见 P0-005。

## 背景

用户同意完善配置、备份和存储故障修复流程。当前 schema4 持久化存储故障；unknown 核查不能清除它。程序升级和回退需要可信的数据库快照与安全恢复入口。

## 决定

- 使用显式指定的版本化 JSON 配置，程序默认值、配置、环境变量、CLI依次覆盖。相对路径按配置目录解析，配置不承载批准或发射状态。
- 使用独立离线维护 CLI，与 daemon 共用数据库锁。备份使用 SQLite 一致快照，记录版本、hash、计数和状态，并检查完整性。
- 恢复写入新的数据库路径，保留原数据库和备份。恢复后撤销旧批准、终止开放提案、把 running 记为 unknown，保留 unresolved 与 storage_fault 阻止，增加 generation并审计。
- 存储故障核查需先停 daemon、明确人员/原因/停发声明、成功生成解除前备份，再验证写事务、撤销旧批准并审计。不能解除 unknown 或不明阻止原因，不能自动重发。
- 维护细节归 journal 模块，不增加发射 RPC 或使核心依赖 SQLite。

## 取舍与边界

离线维护避免在发射状态机中加入备份长任务；需要用户停机。新路径恢复增加一次人工切换配置，保留回退依据并避免覆盖原库。快照与hash用于一致性和误修改检查，同一 OS 用户仍是访问边界，不提供对恶意同用户程序的隔离。

故障解除验证可写性和记录人工核查，不修复损坏数据库或硬件。Phase0仅Fake设备，真实后端启用前须重新核查维护与停发流程。首版不建设热更新服务、后台备份调度或协作平台。
