# ADR 0004：Windows / Linux 共享核心与本地控制适配

- 状态：接受（用户确认总体方案）
- 日期：2026-10-05

## 决定

同一 TypeScript/Node 核心支持 Windows 原生与 Linux 原生。Linux 保留 Unix socket，Windows 增加命名管道，本地 NDJSON 命令与确定性授权/恢复语义共用。不以 WSL 验证替代 Windows 验收。

先验证两平台 Fake 闭环、配置与备份恢复，再加入 IC-7300 USB CI-V 只读接入。真实 CW 键控另行确定并验收，USB 直连不等于已确认 DTR/RTS 分配。

## 实施边界

- 本地端点与文件路径分开处理；Unix 0600 行为保留，Windows 验证命名管道实际 ACL 与访问边界，不能仅因本地通信而声称只允许当前用户。
- 保留 version1 Linux 配置及既有命令兼容路径。新端点配置使用明确的兼容/版本策略；不修改数据库 schema 或发射契约。
- 新增明确的正常停机控制入口，先停止接单、撤销授权、有界取消在途任务，再关闭数据库和释放锁。Windows 强制结束是崩溃，不依赖 POSIX 信号回调保证停止。
- 停机请求需沿用本地控制的授权边界，返回请求已接受与进程已退出分别验证。重启不自动重发。
- 同一 USB 串口由唯一设备持有者协调 CAT 与后续键控，不创建独立争抢同端口的适配器。
- Julia/MWORKS 计算环境保持现有已验证范围，Linux 本地计算支持另评估。

## 原因与后果

用户明确要求 Windows 和 Linux，同时 IC-7300 已 USB 直连。平台适配集中在端点、生命周期与串口边界，避免复制业务状态机。增加两平台测试及权限验证成本；Windows ACL 或串口控制线问题不得以放宽授权绕过，需反馈证据及最小调整。
