# Windows 成品分发要求

日期：2026-10-06。状态：用户已确认产品目标；技术选型与实现尚未验收。

## 用户与平台

主要使用者为用户的同学和学弟，主要交付 Windows 原生版本。Linux 继续支持，
主要供开发者本人使用，也会对外公布。两平台复用核心契约与控制语义。
开发机及 WSL 测试不能替代 Windows 成品验收。

AI 的接入方式、用户配置和成本需要纳入分发设计；服务商、付费方与部署方式
尚未确定。讨论输入见 `ai-distribution-options.md`。

## 成品体验

- 接收者不需要 Node.js、编译器、源码或开发命令即可启动程序。
- 提供日常操作界面；CLI 用于开发、诊断和自动验证。
- 依赖组件随发布包交付并自动管理；后台进程无需使用者手工启动。
- 首次使用可选择 IC-7300 串口、检查设备连接和配置，展示明确的运行状态。
- 允许程序放在 D 盘；日常运行以普通用户权限为目标。
- 缺少设备驱动时给出明确诊断与安装指引；驱动安装可能需要系统管理员权限。
- 未接电台时仍可运行离线演示，不把演示成功表述为真机验收。

## 数据与维护

每位使用者有独立的个人配置与通联数据。程序升级不得覆盖这些数据，
保留版本检查、备份、迁移和恢复路径。发布包不携带开发者个人数据、
绝对路径、账户 SID 或凭据。诊断导出用于反馈问题，默认排除秘密，
说明日志可能包含呼号和设备信息，并由使用者决定是否分享。

## 发布验收

1. 在未安装开发工具的 Windows 环境完成获取、启动、首次配置、退出和重启。
2. 验证路径含空格、程序位于 D 盘、普通用户权限及每台电脑的实际账户隔离。
3. 检查后台组件启动失败、崩溃和主程序退出时的可见状态及进程清理。
4. 验证更新保留个人数据、备份可检查、恢复可执行、诊断包可导出。
5. 成品分发前具备实际可用的最小操作界面，不要求使用者执行 CLI 命令。
6. 真机连接、键控与发射分别验收；本要求本身不授权真实发射。

## 待定选型

安装包或便携包、界面框架、支持的 Windows 版本与架构、发布运行时及更新
方式尚未确定。优先评估便携包，不能把建议写成用户已指定的实现。
开发机已有 Julia/MWORKS 不代表可以随包分发；计算功能的依赖和许可需
单独评估，基础程序不得默认依赖接收者拥有 Syslab。

Windows 管道桥接建议仍需完成架构确认与实施验收，见
`windows-pipe-creation-security.md`。
