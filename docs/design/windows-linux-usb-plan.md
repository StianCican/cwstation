# Windows / Linux 与 IC-7300 USB 最小接入方案

日期：2026-10-05。状态：用户已同意总体方案与实施顺序；具体实现和证据仍需验收，不授权真实发射。

## 已确认目标

电台为 ICOM IC-7300，当前 USB 直连电脑；Windows 和 Linux 都要支持。建议分别验收 Windows 原生 Node 和 Linux 原生 Node，WSL 继续作为开发环境。两平台复用同一核心、CLI、SQLite 及版本化命令协议，每次仅一个系统/进程持有电台 USB。

## 当前差距

- `packages/daemon/src/paths.ts` 把本地端点当文件路径处理。
- `packages/daemon/src/server.ts` 对 socket 执行 chmod、exists、rename；这些操作不能原样用于 Windows 命名管道。
- `apps/daemon.ts` 与 `tests/helpers.ts` 依赖 SIGTERM/SIGKILL；Windows 的进程终止不能假定会调用优雅关闭处理器。
- 配置当前为 version1，`socketPath` 按目录解析；命名管道名称必须与普通文件路径区分。
- 尚无串口后端；已有 DB/socket 锁不等于 OS 设备独占。Windows 大小写路径别名、锁存活检查和文件发布行为亦须实测。

## 推荐最小方案

| 范围 | Linux | Windows |
|---|---|---|
| 核心与业务协议 | 共用 TypeScript/Node 核心 | 同左 |
| 本地 IPC | 保留 Unix socket、0600 | 增加命名管道适配，验证访问权限 |
| 设备入口 | USB 串口设备路径 | COM 端口 |
| CAT 与键控 | 同一设备持有者协调 | 同左 |
| 状态/核查 | 相同授权及恢复语义 | 同左，独立验收退出行为 |

端点种类与配置兼容需明确后再修改公共接口，保留现有 Linux 配置的兼容路径。Windows 命名管道不能以“本地”推断为仅当前用户可访问：先验证默认 ACL 与实际隔离能力，不满足要求时反馈最小替代方案，不能宣称沿用了 Unix 0600 边界。

串口优先评估成熟的跨平台库或已有控制组件；正式任务须固定选型、版本及开口控制线行为。只读 CI-V 第一阶段不驱动 SEND/KEY。CAT 命令确认、串口控制线释放和物理停止证据需分开；共享 USB 连接由同一持有者协调，避免两个模块重复打开同一端口。

Windows 正常停机需要可测试的明确控制入口；强制终止按崩溃恢复处理。新停机入口的权限、拒绝新请求、撤销授权及有界停止语义须一并讨论。

## 建议实施顺序与验收

1. 跨平台离线基础：平台端点、配置兼容、停机和测试进程清理；Windows/Linux 各运行构建、Fake 闭环及备份恢复测试。检查用户隔离、重复实例、重启、路径别名和输出不覆盖。仅 WSL 通过不能记为 Windows 通过。
2. USB CI-V 只读：先协议模拟器，再两平台真机读取频率/模式及断连恢复。实际设置由用户确认；首次开口前禁用电台 USB SEND/CW/RTTY 键控映射，防止 DTR/RTS 初始变化触发发射。状态未确认时不允许真实发射。
3. CW 键控方案：比较电台 CI-V 发码能力与 USB DTR/RTS 等路线，核对手册、时序和停止证据后决定。不能用 Node 定时器的 Fake 结果推断真机 CW 时序合格。
4. 授权、取消、拔插、退出与重启通过后，按有人在场的假负载任务验收。首次真实发射不属于前两步。

Julia 计算模块继续沿用已验证的 MWORKS 环境与文件接口。控制核心双平台目标不等于当前 Julia/Ty 库已在 Linux 验收，计算产物跨平台使用与 Linux 本地计算支持分开记录。

## 下一项讨论

用户已同意“共享核心 + Linux Unix socket / Windows 命名管道”，先完成双平台 Fake 闭环，再做 USB CI-V 只读接入。决定见 ADR0004，首项执行任务见 P1-002；USB 与键控后续分别交接。
