# P2-002：设备持有者与受控写入设计

状态：v3协议明确版，Codex已处理REV-002意见，可作为Fake IPC任务基线；实现须通过阶段检查和交付审议。真实端口迁移和写入另验收。

## 当前问题

`rig-statusd` 当前独占 COM17，并且只允许 CI-V `03`/`04` 读取。真实发射不能再启动第二个进程打开同一端口，也不能把通用 `write(bytes)` 暴露给 CLI 或 AI。

## 候选方案

| 方案 | 设备持有者 | 优点 | 主要问题 |
|---|---|---|---|
| A | 扩展 `rig-statusd` | 改动较小，保留现有监视客户端 | 服务同时承担读写，需严格分隔只读和受控能力 |
| B | 新建 `rig-controld`，迁移 `rig-statusd` 为客户端/兼容入口 | 设备能力边界清晰，便于后续多设备 | 需要一次 IPC 和启动迁移 |
| C | 另起发射进程打开 COM17 | 实现表面简单 | 违反唯一持有，CI-V 无事务 ID，禁止采用 |

## 推荐

采用 B 的逻辑边界，分阶段实现：

1. 设备服务是 COM17 的唯一持有者，负责串口生命周期、CI-V 帧解析、连接代次和设备能力声明。
2. 只读 `status/watch` 保持现有输出兼容。控制服务中的reconnect/close属于控制动作，发射期间只读客户端无权触发；旧只读服务本轮不迁移。
3. 受控写入只接受结构化操作，例如 `cw.send` 和 `cw.stop`，不接受任意字节。
4. TypeScript daemon 内的 `TxController` 仍是唯一批准、互锁、超时、审计和 unknown 状态的持有者；它通过受限 `RemoteKeyer` 调用设备服务。
5. 设备服务拒绝没有匹配连接代次、频率/模式上下文或能力声明的控制请求；断线、状态改变和服务重启都使在途操作无法证明完成。
6. CLI、界面和 AI 只能访问 daemon 的提案/批准接口，不能直接访问设备服务的写入方法。

## IPC 最小契约（草案）

- `device.capabilities`：设备型号、CI-V 地址、支持的操作、连接代次。
- `device.snapshot`：频率、模式、连接状态和采样时刻；明确为非原子快照。
- `cw.send`：调用方在发送前生成稳定operationId（使用proposal.id，不允许追加attempt获得新发射），参数绑定设备实例、文本hash、频率/模式、连接代次、许可代次及期限。
- `cw.stop`：带独立stopId和目标operationId；抢占普通请求，但不插入正在写入的CI-V帧。返回停止证据等级，不直接宣称取消成功。
- `device.close`：撤销在途许可并有界关闭串口。

服务端不得提供 `raw.write`、任意命令号或任意十六进制参数。

## v2执行范围与阶段检查

P2-002只实现独立Fake设备服务、生产候选IPC编解码/调度及RemoteKeyer。Fake实现不导入serialport或真实串口工厂，不接受--port，不改rig.sh和现有状态服务。Fake完成证据只表示模拟后端完成，不允许用于IC-7300能力声明。

检查点：协议与状态表审议通过后开工；首次跨进程send/stop完成后自查；完成故障矩阵后DSH自查、Codex复核。任何真实设备或公共核心契约变更必须升级设计。本草案不是启用真实写入的授权。

## 操作标识、重复和持久化

RPC关联id与业务operationId分开。请求为protocolVersion:1、id、method、params；响应回传对应id，结果包含operationId、deviceInstanceId、connectionGeneration和结果证据。未知版本/字段、超长帧、非法类型拒绝；单帧上限16KiB，单连接待处理请求上限32，队列上限32，写入/请求/关闭均有有界期限。版本不兼容时明确失败。

业务键为设备实例+proposal.id；绑定全部内容和上下文的摘要。首次接受前记录intent，成功写入intent后才可触发后端。同键相同内容返回原记录或运行中状态，不再次执行；同键不同内容拒绝冲突。token及RPC id变化不得改变业务键。禁止在超时、断线、重连或恢复后自动重发。

deviceInstanceId为账本关联的稳定配置设备标识，重启不变；serviceInstanceId每次启动随机生成，用于识别旧会话回复。连接代次跨服务重启配合serviceInstanceId比较，不能仅依赖每次从0开始的整数。设备身份无法核实时拒绝复用原批准；不能换deviceInstanceId绕过unknown账本。

设备服务必须有独立操作账本：Fake阶段可用显式临时数据目录的版本化JSONL（串行追加、intent刷盘后执行），不改核心SQLite schema。重启将遗留intent/running视为unknown并锁住新send，旧键仍不可重发。账本损坏、写入失败或不能确定恢复结果时禁发；不通过删除账本解除。生产持久化介质及unknown人工解除接口单列任务；Fake unknown仅通过新隔离测试实例开始后续用例，不声称恢复真实许可。

拒绝发生在intent之前时只返回拒绝、无设备副作用；intent之后发生不确定故障时记录unknown。RemoteKeyer不得把任意异常或AbortSignal已触发转换为KeyerAbortError；现有控制器保守映射为unknown，后续要增加“已证明未启动”的结果类型时另审议公共契约。

## 完成与停止证据

| 证据 | 可说明的事实 | 终态 |
|---|---|---|
| validated / intent_recorded | 请求检查通过/已登记 | 不是完成 |
| frame_written | 帧已交给传输层 | 不是完成或停止 |
| command_accepted | 收到目标设备命令接受应答 | 不是完成或停止 |
| backend_completed | 后端提供操作关联的可靠完成依据 | completed（仅后端能力覆盖范围） |
| backend_stopped | 后端证明目标操作已停止且不会再排队执行 | cancelled |
| stop_requested / 无回复 / 证据不足 | 停止请求已发出或结果不确定 | unknown |

Fake后端可以模拟backend_completed/backend_stopped；IC-7300目前两项能力均unknown/false。不能用0xFB、零功率、按键时长估算或TX瞬间为RX证明队列已清空。真实适配器在证据路线未成立前不开放send。

RemoteKeyer返回核心所需的requestId=proposal.id，先校验响应关联及设备/上下文；错误关联、超时、迟到回复不覆盖已确定unknown。AbortSignal触发时立即发独立stop请求；仅backend_stopped才允许cancelled。核心的超时/断线/状态变化规则继续适用。

## 许可与控制通道

只读公共端点仅允许status/watch；控制通道独立。Fake首版由daemon启动子服务并通过继承的双向管道通信，用真实NDJSON字节流验证跨进程行为，不暴露公共写端点。生产Unix/Windows控制通道是否采用继承句柄或受保护socket/pipe单独适配验收。

通道启动时私下交付随机会话密钥，不在argv、公开状态或日志中输出。设备服务绑定唯一控制会话；每次send携带随机nonce与HMAC-SHA256 token，按版本化固定字段序列绑定operationId、deviceInstanceId、文本hash、频率/模式、连接/许可代次及expiresAt。采用结构化固定数组JSON编码，双方复算且恒时比较；期限不得超过本次批准期限，服务端限制为最多60秒。nonce首次登记消费，重复业务键仅查询已存在结果；换nonce仍不能执行已登记业务键。token仅供受控daemon使用；内容hash复验不能代替身份验证。失联即撤销会话和未使用token，停止在途操作，证据不足锁为unknown。stop不要求尚未过期的send授权，但必须来自有效控制会话并绑定目标操作，避免授权过期阻止急停。

同OS用户仍是信任边界：此方案不声称能隔离具有任意shell/调试/读取父进程能力的同用户AI。AI只能接提案接口；强隔离要另行配置OS账户/设备权限，不以0600或token作虚假保证。

## 上下文、长度和调度

设备能力声明包含最大字节数30、字符集版本、支持的完成/停止证据、deviceInstanceId、连接及许可代次。设备服务拒绝非CW上下文。批准前按能力检查文本；执行前重新校验完整hash、期限和设备状态，绝不截断或自动分块。

频率/模式读取为非原子快照，有采样时刻和有效期；状态过期或代次不同拒绝send。真实IC-7300的VFO/split/RIT/XIT/实际TX频率及CW-R支持未验收，不能把RX频率当成已证实TX频率；生产preflight另设计。

串口所有操作由单一仲裁器调度，只能有一个在途send。stop撤销许可，丢弃尚未执行send，优先于轮询；正在写入帧不可交错，只等待其有界结束/超时后处理停止。超时导致unknown，不能承诺失效串口仍能执行停止。独立硬件停发保障另验收。

普通队列满时仍保留一个stop/close控制槽；同目标重复stop合并，拒绝无限停止请求占用内存。过载或输出背压不能阻止服务内部撤销许可与有界停止；IPC故障同样触发本地失联处理。

connectionGeneration仅在连接重建/失效时变化；permissionGeneration在撤销许可时变化。重连/关闭先禁新send并撤销许可，再处理在途stop，证据不足unknown，然后有界关闭。未确认关闭时不打开新串口、不报告已释放。状态事件送达daemon以撤销批准；不能只靠客户端缓存。

## 真实持有者迁移与回退（后续阶段）

采用B：先停止旧rig-statusd并核查端口释放，再由rig-controld独占打开；失败则禁止写入并显示诊断。不得并行启动两个持有者；不能用pid文件代替OS独占。doctor显示服务实例、端口、只读/受控能力和实际生命周期。

兼容客户端经新服务只读端点获取原状态结构；旧rig-statusd兼容入口如保留只能作客户端。回退前禁新send、撤销批准、处理unknown、有界关闭新服务并确认端口释放，再恢复旧只读服务。不能让旧版本自动重放新服务账本；用户数据/历史保留。当前rig.sh、COM17链路不迁移。

## Fake IPC验收矩阵

| 场景 | 预期 |
|---|---|
| 正常send及可靠完成事件 | 完成一次，记录证据 |
| 后端已执行但响应丢失 | unknown，零自动重发 |
| 同键相同内容重复/同键不同内容 | 原结果或运行中/冲突，键控次数不增加 |
| stop在send前/帧写入中/接受后 | 未启动不键控；帧无交错；有停止证据cancelled，否则unknown |
| daemon失联/崩溃 | 撤销会话、尝试停止、无证据unknown |
| 服务重启且有intent/running | unknown锁定；旧键不可重发 |
| 迟到/错误id/错误设备回复 | 不覆盖结果、不认作当前操作 |
| write挂起/断线/账本故障 | 有界失败，无假成功、无重试 |
| 重连/关闭与send竞态 | 撤销许可、拒绝新send、未释放不重开 |
| 第二控制客户端/错误token/过期上下文 | 副作用前拒绝 |
| 超长/畸形/未知版本/满队列 | 有界拒绝，停止仍可处理 |
| 退出与恢复 | 无残留子进程/句柄；账本和审计可复核 |

上述测试必须走同一IPC解析和调度代码，至少一组真实跨进程字节流，不能仅直接调用Fake对象。结果、命令、环境、基线和未覆盖项按任务自查规范提交。

## v3明确线格式、认证和生命周期

线上只使用对象式NDJSON。固定数组仅是HMAC输入，不是第二套线格式。cw.send params精确字段为operationId、deviceInstanceId、serviceInstanceId、text、contentSha256、frequencyHz、mode、connectionGeneration、permissionGeneration、stateGeneration、expiresAt、nonce、token。签名输入为JSON.stringify([1,"cw.send",operationId,deviceInstanceId,serviceInstanceId,contentSha256,frequencyHz,mode,connectionGeneration,permissionGeneration,stateGeneration,expiresAt,nonce])。contentSha256复用核心contentHash（绑定文本、频率、模式）；token为hex HMAC-SHA256。RPC id用于传输关联，不参与业务去重。

cw.stop params精确字段为stopId、operationId。stop仅凭已认证继承通道的当前会话授权，不使用send token，不检查旧send批准期限；服务端失联后由本地故障处理停止，不依赖向失效通道再发请求。重复stopId不同目标拒绝；相同目标返回既有停止结果。stop结果回传stopId及operationId，RemoteKeyer只将对应目标证据映射到transmit结果。

device.capabilities、device.snapshot、device.close params为空；operation.get params仅operationId，纯查询不触发后端、不解除核心unknown。初始私有hello帧携带会话密钥与稳定deviceInstanceId，服务确认后才接受业务帧；该帧不进入日志，stdout仅协议帧，stderr仅不含密钥的诊断。所有业务响应包含protocolVersion、id、ok和result或error；方法特有数据在result内。未知方法/非法结构均有语义错误，无后端副作用。

能力响应明确backendKind:"fake"、evidenceSource:"simulation"、maxMessageBytes:30、charsetVersion:"ic7300-command17-v1"、可靠完成/停止模拟能力。snapshot包含Fake频率、mode:"CW"、采样时刻和两种设备代次；Fake频率是模拟TX上下文。device.close关闭Fake后端会话、停止轮询、拒绝新send并有界处理在途结果，不涉及真实串口；close不必退出服务，以便查询账本。reconnect重建Fake后端会话，deviceInstanceId不变、connectionGeneration递增，unknown仍阻止send。

设备服务独立进程由调用方（daemon或测试宿主）监督，独立指进程边界，不指脱离父进程生命周期。宿主选择账本目录，子进程stdin/stdout为私有通道；stdin EOF触发本地禁发、停止、刷盘及有界退出。宿主正常退出等待子进程关闭，超时终止并记录未决状态；不自动重启/重放。测试可直接启动同一子进程，不要求生产daemon接入。生产daemon集成单列后续切片，不改默认FakeKeyer入口。

stateGeneration取核心Proposal/Approval.stateGeneration并校验两者一致；connectionGeneration由设备会话维护，permissionGeneration由设备服务维护，初始化0，在stop/close/断线/上下文改变时递增。服务经snapshot/响应通知宿主；宿主收到变更先让核心setState撤销旧批准，重新获取上下文并提案。三种代次各司其职，不相互替代。

RPC超时后RemoteKeyer锁住本次结果为unknown、尝试一次stop，不重发send。operation.get或服务后来的完成记录只作诊断，不能覆盖核心已落盘unknown。设计版本v3与线协议版本1分别记录。

## P2-002b实施澄清（2026-10-12）

Fake服务的stateGeneration是最后成功刷盘接受的核心代次：新操作拒绝回退，更高代次可接受；账本恢复最高值。它不拥有核心当前授权真值，当前P/A一致与撤销仍由TxController和RemoteKeyer负责；设备connection/permission代次独立校验。
Fake snapshot时效上限2秒。Windows同机子进程Date.now实测存在细小采样偏差，适配器只容许最多20ms未来偏差，超过即拒绝，不延长提案/批准期限。总deadline使用Node timer覆盖整次操作；生产动态设备状态事件与更稳健时钟机制仍须另验收。
