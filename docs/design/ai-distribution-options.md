# AI 分发方案讨论

日期：2026-10-06。状态：用户已同意首版分发方向；具体后端未选型，功能未实现。决定见 `../adr/0005-AI分发与权限边界.md`。

## 已确认背景

Windows 是面向同学和学弟的主要成品；Linux 主要由用户自己使用，也会
对外公布。用户已同意优先支持自备云端 API 凭据，由使用者承担调用费，预留本地模型接口；首版不建设作者统一托管服务。具体模型和服务商未定。
既有架构要求 AI 只提出建议或提案，核心负责确定性授权、互锁、急停和恢复。

## 已确认方向

基础台站可独立使用，AI 为可配置能力；首次运行不因缺少模型账户而无法操作。
应用内提供模型连接配置、连通性检查和明确的可用状态。云端与本地后端通过
同一适配接口接入，不复制台站业务规则，也不假设所有兼容接口能力完全相同。

| 方式 | 接收者需要准备 | 成本与维护 | 建议 |
|---|---|---|---|
| 自备云端 API 凭据 | 个人账户、凭据与网络 | 接收者支付调用费；程序维护适配器 | 首版优先支持 |
| 本地模型服务 | 足够的硬件、模型和运行环境 | 无云端调用费；有安装、存储和算力成本 | 预留接口，接入另验收 |
| 作者统一托管服务 | 登录或使用授权 | 作者承担服务、额度、滥用控制和运维 | 首版不建设 |

不能把作者 API 密钥写入发布包。优先使用系统凭据存储，升级保留个人设置，
导出配置与诊断时排除凭据。不同 AI 产品的聊天订阅不自动等于 API 调用权限。

## 能力与故障边界

先评估解释设备状态、生成待确认的 CW 内容及通联建议；解码和实时键控
不默认交给大语言模型。AI 输出使用结构化提案，由核心检查字段、当前状态、
频率/模式和批准有效期；AI 不获得任意 shell、串口、批准或解除故障工具。
尤其不能仅靠提示词限制同用户下具有任意 shell 权限的外部 Agent。

断网、超时、模型拒绝或输出无效时，显示 AI 不可用，保留人工操作。
不得自动重发控制命令，不自动换到另一服务商上传数据。云端发送的呼号、
交换内容和日志范围须让使用者明确选择，不默认上传完整日志或原始音频。

## 下一步需确定

- 首批 AI 场景及其验收标准，而非先围绕某个模型建设整套平台。
- 自备凭据的首次配置体验与本地模型接口能力；预留接口不代表随包提供模型。
- 支持的后端、配置方式、请求预算、上下文范围和发布包依赖。

Windows 打包必须验证未安装开发工具时的模型配置、凭据保护及故障降级；
本地模型作为可选能力时，缺少它不能阻止基础台站启动。
