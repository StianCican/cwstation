# P2-012 真实只读持有者接入设计 v4

日期：2026-10-14，v4（内容经DSH v4定点审议，版本标签收口）。Codex设计，DSH审议；本稿是接入前设计，不是设备操作授权，也不是公共契约的完整实现基线。

## 目标与边界

把 P2-011 的六项只读上下文读取接入唯一设备持有者，同时保持现有 `status/watch/reconnect` 兼容。第一阶段只允许读取：TX频率、RX/TX状态、Split、RIT、XIT、BK-IN。禁止发送 CW、PTT、停止消息、通用 raw write 和自动重试。

`rig-statusd` 现有真实只读链路继续作为当前生产路径；迁移前不能让新服务并行打开 COM17。候选实现应由 `rig-controld` 统一持有串口，旧入口改为只读兼容客户端或保持停用，具体迁移必须单独验收。当前 `rig.sh -> rig-launch -> rig-controld` 最终委托旧只读 main，迁移时停止对象必须按实际进程链核对，不能只按文件名停止。

## 设备持有者契约

唯一持有者负责串口打开/关闭、CI-V解析、连接代次、查询调度和能力声明。所有读取请求经结构化操作名进入，不能暴露任意字节写接口。每个连接代次生成实例标识；断线、重连、配置变化时旧视图和旧批准指纹全部失效。

### 单 transport 仲裁

03/04旧状态读取和P2-011六项读取必须进入同一个队列、同一个帧解析器和同一个在途槽位；不能让两个session分别订阅同一串口。调度器只允许一个CI-V查询在途，完成、超时或故障后才取下一项；上下文批次不能绕过03/04的互斥锁。正常轮询优先保证03/04每个状态周期一次；上下文批次只填充两个状态轮询之间的空隙，单次批次最多六项，不能延长下一次03/04期限。`refreshAll/read` 与轮询同级排队，不插队、不丢弃已开始查询；`reconnect/close` 进入控制闸门，先禁止新查询，等待或取消在途并按连接代次锁定结果。每项查询保留本地请求ID，回复按目标地址、命令和子命令匹配，迟到回复只丢弃并记录诊断。上下文读取故障锁定该连接代次并使旧状态视图 stale；不会自动重试或并行开第二transport。六项读取的白名单扩展和03/04保持为两个窄操作集合，不能改成通用write。

能力声明分为稳定设备身份和运行实例两层：`deviceInstanceId` 必须来自明确配置/可核查硬件身份，不能由COM端口名推导；`serviceInstanceId` 每次服务启动变化；`connectionGeneration` 每次连接/配置变化递增。运行层包含端口、波特率、CI-V地址、支持的只读字段、只读能力版本和 `transmits:false`。新增字段必须进入能力指纹，能力变化即撤销旧批准。能力未知或声明缺项时，读取可显示 unknown，但不能用于批准；不能改写现有顶层 `source:"rig-statusd"`，上下文使用独立的 `contextSource:"serial"`。

公共 `status/watch` 继续使用协议版本1并以可选嵌套 `context` 扩展，旧客户端忽略该字段；不在本阶段把公共版本升到2。若未来必须升版本，须同步更新 `ReadOnlyRigApprovalGate` 并单独迁移。私有控制/仲裁通道另用明确版本和代次字段，拒绝未知操作、错误代次和超出大小限制的请求。读取响应必须带请求ID、服务实例和连接代次，不能把CI-V帧本身当成事务证明。`contextSource` 唯一取值为 `simulation|serial`，不得复用顶层 `source`。

## 迁移顺序

0. **硬件通知门**：在停止旧持有者或打开COM17前，Codex必须先通知用户并取得本次真实只读操作的明确授权；用户确认零功率、USB SEND/USB Keying(CW/RTTY)及外部控制线设置，并保留 `--confirm-keying-off` 硬门。未完成即停止流程。
1. 先禁止新的控制提案并撤销受影响批准，保存当前诊断和端口归属；本只读阶段没有在途发送时，显式记录“unknown处理不适用”。
2. 按实际进程链停止旧持有者，确认监督进程退出、close完成，并通过OS级独占打开探测或等价可复核证据确认COM17已释放；不满足则禁止启动候选持有者。
3. 以显式白名单和只读能力启动候选持有者，首次只查询旧 03/04，再单独启用 P2-011 六项查询。
4. 监视客户端通过兼容只读投影获取数据；上下文字段以 `contextSource=serial`、实例和代次标注，不能沿用 simulation 视图。公共只读客户端可以请求 `status/watch`，不能直接请求 `reconnect/close`；现有监视台的 `C` 保持兼容，但改为经本机受监督服务的专用维护RPC转发，不授予监视进程串口权限。
5. 发生写入失败、断线、未知关闭或能力不完整时锁定服务，撤销旧批准，停止新增查询；不启动第二持有者。`reconnect/close` 仅由本机受监督服务控制通道触发，或由明确的本机维护命令在无在途操作时触发；公共监视客户端和AI提案不能直接触发。每次成功重连递增 `connectionGeneration`，旧响应和批准立即失效。
6. 回滚前同样确认候选服务退出和端口释放，再恢复旧只读路径；只读阶段无发送账本可重放，不恢复旧批准。公共监视台仍只能通过只读投影连接，不能自行打开串口。

## 接入前检查

- 静态：公共类型、版本兼容、唯一持有者、关闭/重连和未知状态语义通过设计审议。
- 离线：Fake transport 覆盖同步响应、迟到响应、超时、批次失败、close 挂起和代次变化；本轮不新增或运行测试，待用户明确授权后执行。
- 设备前置：用户确认 IC-7300 保持零功率/不发射；USB SEND、USB Keying(CW/RTTY)及外部控制线设置按既有记录复核；确认实际端口和 19200 波特率。
- 真机阶段仅读取并观察返回，不发送设置或CW。任何字段 unknown/stale/locked 都不得用于批准；若需执行任何写入，必须另立设计、批准和验收。

## 验收与未决项

验收必须分为离线会话、候选服务静态/编译、真实只读链路三类证据。真实阶段需要用户在监视台运行后转动频率旋钮、切换模式并观察上下文字段；USB拔插后通过监视台 `C` 的专用维护RPC重连，并单独记录服务实例/连接代次变化。任何一类证据都不能替代另一类。

未决：`deviceInstanceId` 的具体硬件身份来源、`rig-controld` 与旧只读 main 的解耦实现、能力摘要持久化位置、服务监督和 Windows 命名管道权限、监视台 `context` 字段的最终映射。上述事项冻结前，不接入COM17，也不声明新字段已可用。

## Codex最终裁决与实施前待办

DSH四轮审议完成，最后一轮无未解决S0/S1/S2；Codex仅验收本稿为接入方向和后续设计输入，不冻结公共契约。以下由Codex在实现任务前明确，不能仅以S3评级跳过：队列长度/取消上限、上下文批次插入与03/04截止期的可实现调度规则、每字段TTL、控制闸门等待/取消期限、维护RPC认证载体和权限校验、能力字段的具体schema与摘要以及稳定硬件身份来源。当前“不能延长期限”是调度目标，不是物理保证；CI-V晚到的同形帧无法凭本地ID可靠辨认或保证丢弃，故障后必须关代次，不能据此形成批准证据。

现有只读查询也会调用transport.write发送读请求，因此“写入失败”指读请求写出失败，仍属于只读故障处理，不是发送CW授权。重连代次必须在连接失效/重建开始时撤销旧结果，不能等成功后才失效。真实端口释放探测也属于需提前通知的设备操作，不得作为未通知开口的例外。
