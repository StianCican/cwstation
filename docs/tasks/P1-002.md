## 实现要求

1. 小范围平台端点辅助：Linux 文件 socket、Windows 本地命名管道。管道不得经过 resolve/realpath/chmod/rename；管道锁在实际用户运行目录，名称与锁 key 规范化，拒绝远程管道与危险/不支持格式。Linux 配置、环境、CLI 兼容保持。
2. 配置：继续读 version1；新增能力用 version2 明确表达平台端点（可保留 socketPath，但管道语义仅新版承载）。优先级默认<配置<环境<CLI，严格验证，不将管道相对配置目录解析。旧版 Linux 配置原样可用；跨平台不兼容地址清晰拒绝。不静默把用户指定的 Unix 文件改为 Windows 管道。
3. Windows 默认端点应区分用户，锁/PID 存活/路径别名与大写小写需评估。用原生 Windows Node 验证，不能由 platform mock 替代。对命名管道 ACL 进行实际检查，可用 PowerShell 只读 Win32 查询；不得只报告“本地所以安全”。默认 ACL 不满足同用户控制边界时先报告具体权限/可达性及最小修正建议，不自行扩建权限平台或换公开 TCP。不输出私有 token/密钥。
4. 新增 `cwctl stop`/RPC `daemon.stop`：严格空参数，响应只表示停机已接受，响应发送之后触发共享 shutdown 路径；关闭入口幂等，接受停机时即拒绝同一连接及新连接的其它工作。既有 SIGINT/SIGTERM 使用同一路径；撤销批准、在途有界取消、unknown/重启语义保持，持久化失败仍请求取消。不得直接 process.exit 绕过关闭。
5. doctor 如实报告平台、端点种类/访问边界，Fake 标识保持。Windows 未完成访问边界验证不能标验收通过。
6. 测试辅助用实际平台端点与 CLI 停机；Windows 强制结束独立测试恢复。修复 Windows 的 built 路径检测（当前拼接 '/'）。平台独有 Unix 权限/symlink 条件允许有明确理由的跳过，共享核心/维护/状态闭环不得静默跳过。
