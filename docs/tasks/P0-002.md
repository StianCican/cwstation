## 目标及范围

只修改本项目的 apps/、packages/、package.json、tsconfig.json、README.md 和新增 tests/、docs/evidence/P0-002.md。不要修改 MEMORY.md、AGENTS.md、本任务文件、审阅报告，不访问真实电台，不更换系统环境，不读取凭据。沿用 Node 24、TypeScript、内置 node:sqlite，尽量不加依赖。

1. 新增常驻 daemon，由它唯一拥有 TxController、FakeKeyer 和 SQLite。CLI 不直接操作数据库或自动批准。
2. 首版仅 WSL/Linux 本地 Unix socket，使用用户可写运行目录和 0600 socket；不监听公开 TCP。协议版本化，输入运行时校验，限制帧大小、请求时长，错误输出 JSON。安全边界是同一 OS 用户，不能声称 CLI 操作证明真实人类批准；不接 AI。
3. SQLite 持久化提案、批准和结果；状态变更与审计原子事务。显式 schema 迁移，拒绝未来版本；保留现有 v1 数据。server 成功独占 socket 后才执行启动恢复，不允许双 daemon 同时操控同一数据库（锁）。不得盲目删除已有 socket/锁文件。
4. propose、approve、execute/transmit 分离，CLI 跨进程完成流程。批准绑定不可变内容、频率、模式、generation、期限；服务端创建一次性批准。未批准、过期、取消不可发。完成或开始执行即消费授权，同 ID 重复执行返回已有结果或拒绝，绝不再键控。提案使用合理人操作 TTL（如60s）和可限制参数。
5. 发射只有一个在途操作，abort 独立请求可抢占。超时或无法证明停止进入 unknown 并阻止后续执行。重启撤销 pending/approved，遗留 executing 变 unknown，不自动重试。保留历史供查询。结果未知的解除可暂不实现，但需写清。
6. 故障后 fail closed，包括 SQLite 写入失败；在执行副作用前持久化 intent。后台断连/状态改变撤销授权。FakeKeyer 支持可控时长/故障，处理预先 abort、监听器清理。
7. daemon 处理 SIGTERM/SIGINT 停止接单、撤销批准、取消在途、等待有限时间后关闭数据库；避免未完成操作被误记 completed。
8. CLI status、propose、approve、transmit、abort、audit、proposals、doctor；保留 demo 可以但必须显式标记 fake-only，并不能让默认 transmit 自动批准。npm 脚本启动 daemon。CLI 输出纯 JSON，语义退出码。
