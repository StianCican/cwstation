## 最小实施

新增小型C#/.NET Framework桥接程序，Win32创建管道时传SECURITY_ATTRIBUTES：
protected DACL、当前实际token用户与SYSTEM允许、NETWORK拒绝；每次实例设置
PIPE_REJECT_REMOTE_CLIENTS（dwPipeMode），首次FIRST_PIPE_INSTANCE。
保留一个未接单实例保证名字/ACL生命期，避免实例全消失后可抢占。
创建后读回结构验证owner/DACL/ACE才ready，不采用listen后修改或固定等待。
由Node启动，经继承匿名stdin/stdout传递版本化内部消息；无TCP或中间命名管道。
stdout仅内部协议，stderr诊断；限定内部帧、连接数、队列、写等待/启动/关闭超时。
桥接只通信，复用现有NDJSON parser/dispatch/发送和停机flush，不复制RPC业务。
Linux不启动helper。协议1/schema4/用户配置不改；缺helper或失败一律拒绝。

桥接父PID从启动参数核对实际token用户，监测父退出与stdin EOF；无孤儿服务。
Node桥接失联立即停止接单并触发现有有界撤销/取消/停机。
不要在启动编译，提供显式Windows构建脚本，用已有Framework64 csc生成
dist/native/产物；Windows verify-platform构建时调用，Linux无需该产物。
任何helper必须通过process.execPath附近或项目构建路径明确解析，shell:false。

客户端身份核验：仅检验管道名字/首次标志不够。Windows CLI通过同一helper的
client模式持有真实连接HANDLE，GetNamedPipeServerProcessId + OpenProcessToken
核对服务SID与当前用户，核对实际ACL，再发送RPC（同一handle，避免TOCTOU）。
client模式亦通过stdio对Node透明转发，Node Client复用同一响应处理。
信任同用户/SYSTEM边界；不防同用户任意shell的AI，管理员不属对抗范围。
