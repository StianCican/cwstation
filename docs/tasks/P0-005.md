## 已确定方案

1. 版本1 JSON配置独立于代码和数据库。daemon/cwctl/维护CLI显式 `--config <file>`，不自动搜索。配置只支持 socketPath、dbPath 与 daemon 的 TTL/timeout/frame limit 等已存在运行参数；不配置频率、批准或 blocked 状态。相对路径以配置文件目录解析。优先级：默认值 < 配置 < 已有环境变量 < CLI路径旗标。严格拒绝未知字段、未来版本、空路径、错误类型和不合理数字（整数、正值、上限；Fake duration可为0）。原无配置行为与既有环境变量兼容。故障注入变量仍独立使用，不写入普通示例配置。cwctl只取socket，不要求daemon运行即可校验配置。
2. 独立 `apps/cwmaint.ts`，纯JSON输出、明确退出码、`npm run cwmaint`。命令 `backup --db <path> --out <new-directory>`、`inspect --bundle <dir>`、`restore --bundle <dir> --db <new-path>`、`clear-storage-fault --db <path> --operator <name> --note <reason> --confirm-stopped`。严格拒绝非法/重复/缺失旗标、多余位置参数；备份/恢复不自动停止daemon，持有同一dbLockPath锁时拒绝。路径必须绝对规范化并处理已有路径的符号链接，避免别名绕过daemon锁。维护操作必须只针对既有源数据库，不因拼错路径创建空库。
3. 备份必须使用node:sqlite的一致性快照能力（如 VACUUM INTO，在锁内执行；不能裸copy主文件忽略WAL），不使用SqliteJournal构造器迁移备份源。版本化manifest记录schema、时间、数据库文件名/大小/SHA256、数据计数及台站状态。整包先写独占临时目录、校验再发布；输出目录存在则拒绝。失败清理本次临时产物，绝不删除既有用户路径。inspect读-only检查manifest类型/版本/大小/hash、固定相对文件名、无symlink/目录越界、SQLite integrity_check及foreign_key_check，schema只允许本程序支持的既有版本，不写入/迁移源。拒绝缺表或伪造schema（列/必要结构检查）。计数/状态与manifest一致。
4. restore仅允许新数据库路径（主文件及-wal/-shm不得已存在），取得目标锁再检查，检查bundle后从一致快照创建临时DB并校验，在临时DB进行已有显式迁移与恢复：撤销全部批准，取消开放提案，running变unknown，generation增加，保存审计 maintenance.restored；storage_fault与未核查unknown继续阻止。保留原执行与核查记录，不重发、不重新批准。恢复后的数据库处于安全状态才发布；不覆盖源，不提供就地覆盖。失败清理本次临时文件并释放锁。恢复会写新DB，但不能改bundle。
5. clear-storage-fault只支持本项目Fake离线库，并在daemon停止后取得同一数据库锁。要求operator/note长度非空及裸confirm旗标。先只读完整性/版本检查，再成功生成不可覆盖的故障解除前备份（命令返回其路径），之后开启显式写事务检查可写性、撤销所有批准、取消开放提案、running转换为unknown、generation+1、明确清空storage_fault、重新根据全部unresolved unknown设置阻止、追加audit maintenance.storage_fault_cleared（原fault/operator/note/backup路径和hash）。不能清unknown或其他不明blocked原因；没有storage_fault返回冲突，不重复审计。读写/提交失败事务回滚，保持故障。SqliteJournal.saveState的COALESCE保留语义不可随意改成自动清故障；专用清理入口局限维护模块。不声称修复损坏DB、磁盘/硬件故障；该命令仅验证恢复后的存储可写性并记录人工核查。
6. 核心仍依赖存储端口；维护SQLite细节放journal/maintenance模块，不增加daemon RPC、不改发射路径。用当前schema4，无需新表时不升级schema。补README示例、恢复/回退步骤、失败说明；不要求删除原数据库或证据。
