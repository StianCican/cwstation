## 实施六项

1. 缺口：03-C每轮收口后请求模型，03-B只能完整键入原文确认。目标是在同一receive会话中，AI回复时附带至多3条下一轮条件候选；命中不新增网络等待，最终提案可修改后进入同一模拟发送会话。首次请求和未命中仍等待模型，收口等待不变，不声称真实换手提速已测得。
2. 主链：`cwrig receive → rig-receive → ReplySessionImpl → requestChatCompletion`，发送仍为`runCwTrial → CwTrialSession`。DSH修改权仅reply.ts、rig-receive.ts、rig-cw-trial.ts、cwrig.ts usage及tests/receive-reply.test.ts；Codex维护本任务、MEMORY、ROADMAP、README及最终证据。双方不同时改同一文件。
3. 最小设计：显式`--reply-prepared`要求`--reply-continuous`，旧schema/默认行为不改。仅该模式模型输出增加`prepared`数组，每项只含`whenReceived`与`text`。whenReceived为下一轮完整接收文本精确匹配条件（仅首尾/连续ASCII空格归一，不模糊匹配、不正则）；完整正文已知事实由模型准备并经过既有校验，不支持猜测RST/QTH或新增槽位语言。至多3项，条件长度至多160字符，正文仍30字节/大写/禁止^，拒绝未知字段、重复条件、非法/过大结果。候选仅适用本会话下一次收口，命中、未命中、取消、失败、超限、end均消费/清空，不沿多轮复用；准备结果不得宣称已发送。新输入在下一轮收口前继续组报，候选不可按部分文本提前命中。模型当前动作end不保留候选。缓存只附带在现有请求，不后台轮询/新建provider。缓存命中事件明确来源及模型等待0，准备成本归属前一模型请求。
4. 人工编辑与数量：所有进程内reply绑定的模拟确认可用`EDIT <正文>`调整，再展示并要求完整键入最终正文确认。非法正文不发送，重新提示或明确退出；循环有界。编辑中的草稿为runner本地唯一副本，AI不覆盖，取消/上下文失效保留可见草稿且零派发。修改后重新计算fingerprint及记录detail，原提案revision/isCurrent仍检查，真实E/TEST白名单不改。不新增服务、进程种类、依赖、持久化格式、缓存数据库或第二设备控制器；扩展仅可选CLI及该模式JSON输出/模型schema。
5. 接入与兼容：保持03-B及普通03-C行为。仅新prepared模式允许与既有PCM文件/TTY模拟发送组合；正常EOF且最后当前提案为合法reply时交给原runner一次，其他ended/failure/cancel不得派发；此前各轮仅展示，不冒充持续自动发送。不绕过同目录未决intent，不循环建目录或删记录。最终输入后新文本仍撤销旧提案。不是替换设备会话，无旧数据迁移。
6. 验收/保护：基线`.local-backups/20261021-165947-prepared-replies/`含tracked dirty补丁、全部修改目标源码/既有未跟踪专项及文档tar、dist和非凭据profile。仅受影响回复/runner专项、一次build，沿CLI的两轮脚本化模型→缓存命中→EDIT→确认→模拟发送作为闭环；优先把整合证据写进既有专项，不另建产品入口。旧设备/解码/真模型证据沿用，不接电台/天线、无真实模型/凭据读取，不全仓测试。DSH设计若发现根本冲突须带证据停止扩大，否则在本任务已授权范围内实施并自查R01–R13，一份有效测试结果供Codex复核，不机械重复。
