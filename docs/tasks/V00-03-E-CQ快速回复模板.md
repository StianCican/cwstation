## 实施六项

1. 缺口：03-D整句候选实际命中率未知，不能作为通联产品策略。仅覆盖既有receive/reply里最小首轮场景：完整收报必须为`CQ [可选限定词...] DE <显式配置peerCall> K`。实际实现限定词来自`CQ/TEST/DX/QRP/QRO/NA/SA/EU/AF/AS/OC/POTA/SOTA/IOTA`，最多6个；命中以本会话已配置ownCall/peerCall形成`<peerCall> DE <ownCall> K`。其他文本、KN、呼号不一致、缺字段、额外尾词或非法词全部原AI回退。不能只因文本含CQ子串就命中。
2. 主链：`cwrig receive → rig-receive → ReplySessionImpl → requestChatCompletion`，仅调整既有连续prepared分支的收口决策；发送仍`runCwTrial → CwTrialSession`。DSH仅修改`packages/assistant/src/reply.ts`、现有`tests/receive-reply.test.ts`，Codex维护本任务、MEMORY、ROADMAP、README及证据。不增速率/状态服务。
3. 局部实现：显式`--reply-prepared`开启CQ结构化快速路径，不再要求AI输出`whenReceived`整句候选，也不从未发送提案推断状态。符合CQ语法则本地生成有效reply提案，报告明确rule/source及modelWaitMs=0；不符合时用原连续三字段AI schema和同一请求入口。人工EDIT/确认继续沿03-D runner；实际模板正文由校验后的呼号字段构成。
4. 入口/状态/存储：复用现有可选CLI参数、JSONL reply事件和会话内own/peer call，不改持久化格式/配置版本/入口/服务/依赖。AI `prepared`整句候选schema与`preparedCache`事件已从当前入口移除，改用明确`replySource`/`fastPathRule`/`modelWaitMs`字段；旧03-D evidence保留历史含义并注明已替代。静态规则不新增跨通联cache。
5. 兼容/边界：普通单轮、普通continuous、03-A/B/D行为默认不变；显式prepared模式非CQ回落AI。原仅PCM文件正常EOF后一次模拟发送限定继续，人工可EDIT，最终正文重验；不启用真实发送、连续发送、KN、RST/QTH填充，不改未决intent策略。当前没有真实上一报文已发送确认，CQ规则不依赖该状态。
6. 验收/保护：`.local-backups/20261021-184010-cq-template/`保存dirty patch、所有目标基线、dist和非凭据profile。定向用例：CQ TEST DE configured-peer K本地命中且零HTTP；呼号不匹配/其他自然报文各走原模型；近似前后缀/KN/非法token不误命中；命中事件和编辑后模拟发送仍沿原runner；普通旧continuous三字段兼容。只跑受影响reply专项与build，不重跑03-D原有68项/设备/解码/真实模型；若测试直接共享旧专项则只运行同一受影响专项一次。DSH设计若认为场景语义错误，提交证据和最小备选后停止扩建。
