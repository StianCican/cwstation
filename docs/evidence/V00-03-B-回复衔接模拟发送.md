## 用户可见增量与主链

```bash
node dist/apps/cwrig.js receive --decoder <multimon-ng> --pcm-s16le capture.s16le \
  --reply-config <assistant-config.json> --own-call B1AA --peer-call B2BB \
  --reply-trial-simulate --reply-trial-record-dir logs/cw-trial
```

- 主链：`apps/cwrig.ts receive → apps/rig-receive.ts → packages/receive`（原解码不变）`→ packages/assistant/reply.createReplySession`（03-A 原实现不变）`→ apps/rig-cw-trial.ts runCwTrial → 同一 CwTrialSession / 既有模拟 transport / 既有 CwTrialRecordStore`。没有复制预检、确认后重读、intent fsync、一次发送、停止或关闭循环。
- `--reply-trial-simulate` 与 `--reply-trial-record-dir` 必须同时给出；必须同时给出三个回复参数。只接受 `--pcm-s16le <file>`，明确拒绝 stdin（`-`）和实时音频。没有自动确认参数；无 TTY 在启动解码器前返回 2。
- 只有 `status:"published"`、`validated:true`、`action:"reply"`、非空正文才进入绑定。`no_reply`/失败/未发布/取消均不调用 `runCwTrial`，不创建试验记录。
- 绑定正文展示为 `type:"reply_trial"`（`state:"confirm"`、`transport:"simulator"`、`sessionId`/`turnId`/`revision`/`text`/`receivedText`），随后 `runCwTrial` 打印原八项预检并提示键入**完整正文本身**；不一致即退出 3、零发送。
- 实际执行仍为八查询预检、确认后八查询重读、intent 写盘并 fsync、一次 Command 17 正文、一次停止、关闭；模拟 transport 记录正文与停止帧。退出码沿用 `runCwTrial`：0/2/3/4/5/6/7。
- 记录不扩 schema：AI 正文记录的 `message` 仍为 `null`，`detail` 保存精确正文、`sessionId`、`turnId`、`revision` 及既有帧/结果信息。同目录未解决 intent 继续阻断重跑，不删除记录、不换目录绕过。

## 运行时校验与失效

- 绑定正文再次检查：非空、已大写 ASCII、不含 `^`、直接复用 `planCivCwMessage`（字符白名单与 30 字节上限）；`sessionId`/`turnId` 非空，`revision` 为正整数。
- 绑定只允许 `--simulate`；真实 `--port` 路径在打开记录/transport 前返回 2。带绑定同时给 `--simulate-confirm` 也返回 2，不能自动确认。
- TTY 前移到绑定入口：无交互终端时在打开记录/transport 前返回 2，零读取、零写入。
- 正文确认使用严格相等（含空格）；不接受 trim、截断或只输入部分。
- 取消：`runCwTrial` 既有 SIGINT/SIGTERM/readline 关闭路径；intent append 后立即 `checkInterrupted`，因此 fsync 期间失效不会派发。专项用 `io.signal` 在 intent 写入后 abort，断言 0 个 `0x17` 帧且 intent 仍未解决。
- `no_reply`/无效提案在 receive 内直接结束，返回 0 但不调用发送链；专项断言试验目录未创建、提示未发生。
