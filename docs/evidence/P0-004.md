## 3. Morse 编码复用评估（npm morse@0.1.0）

任务要求复用小型现有库并检查实际源和许可证。实际下载 tarball 并逐文件检查：

- `package.json`：`version 0.1.0`，**无 `license` 字段**；`dependencies` 为
  `"optimist": "*"`（未固定版本）。
- tarball 内容：`morse.js`、`map.js`、`tree.js`、`bin/morse.js`、`test/*`、`README.md`；
  **没有 `LICENSE` 文件**。`README.md` 末尾声明 `## license` / `MIT`。
- `map.js`：数据表，含 A-Z、0-9 与标点；`morse.js` 的 `encode()` 对不支持的字符会
  `map[ch] || '?'` **静默返回 `'?'`**；空格被映射为 `'.......'`（不符合标准词间隔，
  因此本实现不把空格交给库）。
- `bin/morse.js` 才依赖 `optimist`；本实现只 `import` 包主入口 `morse.js`，从不运行其 CLI。
- 依赖链 `morse → optimist@0.6.1 → minimist@0.0.x` 存在 critical 原型污染公告。为固定版本、
  消除已知漏洞，`package.json` 增加 `overrides: { "minimist": "1.2.8" }`；`npm audit`
  结果为 `found 0 vulnerabilities`，`npm ls` 显示 `minimist@1.2.8 overridden`。

标准一致性：对 A-Z、0-9 与 `/?.,` 共 40 个字符逐一比对 ITU 标准，库输出全部一致
（`tests/signal.test.ts` 首个用例固定该断言）。按字符调用；`encode` 返回 `'?'` 或非
`[.-]+` 时抛出 `unsupported_character` / `morse_library_mismatch`，绝不静默丢弃。首版支持的
标点就是已验证的 `/ ? . ,`；`()` 等异常映射不进入允许集。

> 遗留事项（供 Codex/用户决定）：该包 README 声明 MIT 但发布物无 LICENSE 文件、
> package.json 无 license 字段，且带 wildcard 依赖。本实现用精确版本 + override +
> 只 import 主入口来降低风险，但仓库层面是否接受该许可证声明仍建议复核。

## 4. 契约与实现要点

| 任务要点 | 实现 |
|---|---|
| `cwwave prepare/verify` CLI | `apps/cwwave.ts`；纯 JSON；退出码 0/1/2/3/4；未知/重复旗标、多余位置参数一律拒绝 |
| prepare 独占写入、不覆盖 | `writeFileSync(..., {flag:"wx"})`；`EEXIST` → `output_exists`（退出码 4）；不启动 Julia、不发射 |
| 参数默认与范围 | wpm 默认 20（5..60）、tone 默认 600（200..2000 且 < Nyquist）、sample-rate 默认 8000（8000..48000 整数）、snr 默认 10（-20..60 或 `clean/none/null`）、seed 默认 42（0..2³¹-1 整数）、ramp-ms 默认 5（0..50）、text ≤ 400 字符、总时长 ≤ 120s |
| 契约版本 | `contractVersion=1`、`algorithmVersion=1.0.0`；未知版本双方拒绝 |
| 双向独立校验 | TS `validateCwTask` 与 Julia `_validate_task` 各自重复范围/类型检查；Julia 额外拒绝非整数冒充、空词、非法 Morse、超量样本 |
| Morse 词表 | `morseWords` 按词分组，每字母为 `[.-]+`，长度 1..7；TS 还校验其等于复用库对 `normalizedText` 的重新编码 |
| 时间轴 | 点 1、划 3、元素间隔 1、字符间隔 3、词间隔 7；点长 `1.2/wpm` 秒；`sampleAt(u)=floor((2·u·sr·6+5·wpm)/(10·wpm))`，TS/Julia 用同一条纯整数公式，避免 .5 舍入歧义 |
| 关键段落 | 由实际样本边界的半开区间 `[startSample,endSample)` 生成，绝不由加噪后反推；末尾不留额外间隔 |
| 短余弦沿 | 每个 key-down 段首尾用 `0.5(1−cos)` 斜坡，`ramp=min(round(rampMs·sr/1000), ⌊段长/2⌋)`，避免硬开关 |
| awgn 与 SNR | `TyCommunication.awgn(clean, snr, "measured", seed; nargout=2)`，使用整段报文（含间隔）的实测功率；记录 `snrDefinition`（SNR 定义）、`noiseVariance`、实测 `measuredSnrDb = 10log10(Σclean²/Σnoise²)` 与 `estimatedNoiseVariance` |
| 同比例归一化 | `gain=0.95/max|noisy|` 同时乘到 clean 与 noisy，峰值 ≤ 0.95，保 SNR、避免截幅 |
| 原子发布 | 输出目录必须不存在、父目录必须存在；先 `mktempdir(parent, prefix=".cwwave-")` 写临时文件，成功后 `mv` 到目标；失败只 `rm` 本次临时目录，不删用户目录 |
| result 内容 | task 原始字节 SHA256、算法/任务版本、有效 params、Julia 与 TyCommunication/JSON3/WAV 版本、seed、时长/样本数、时长与边界量化误差、实测 SNR、keyDownSegments、artifact 相对路径/字节/SHA256、`unrecognizedTaskFields`、`executionControl{interactive:false,transmits:false}` |
| verify 不看 JSON 存在性 | 重算 task/artifact SHA256；解析 RIFF/WAVE 并校验 RIFF size、fmt(16/PCM/mono/16bit/sampleRate/byteRate/blockAlign)；重算关键段落、时长量化；检查峰值、间隔静音、段内能量；用记录增益与 task 参数逐样本重建 clean 载波并比对（锁定波形/相位，拒绝整体反相）；从 clean/noisy 重算实测 SNR 与噪声方差；拒绝绝对/`..`/目录外 symlink 路径、未来版本、错配元数据 |

## 6. Codex 审查发现与修正

Codex 并行加入 `tests/signal-review.test.ts` 与真实 Julia 生成的 `-20 dB` 证据
（`docs/evidence/P0-004-low-snr*`）。初次运行 3 项失败，均为实现缺口而非测试问题，已修正：

1. **低 SNR 误杀**：`verify` 原以固定 `minSegmentPeak ≥ 0.05` 判断段内有能量；-20 dB 时
   clean 被同比例压低到峰值 ≈ 0.047，合法文件被误判 `audio_segment_silent`。改为相对
   阈值 `max(0.25·peakClean, 1e-6)`，仍能发现被清零/截改的段。
2. **增益/峰值元数据未校验**：`normalizationGain`/`peakClean`/`peakNoisy` 原只在部分分支
   隐式读取。新增显式有限数值 + `>0` + 峰值 ≤ 0.95 校验，字符串等异常值统一
   `metadata_mismatch`。
3. **WAV 头校验不足**：`parsePcm16MonoWav` 原不校验 RIFF size、byteRate、blockAlign。
   新增 `riffSize+8 === 文件长度`、`blockAlign === channels·bits/8`、
   `byteRate === sampleRate·blockAlign` 校验。
4. **只校验幅度、未锁定载波**：原检查对整体反相不敏感——把 clean/noisy 全部取反并更新
   SHA256 仍会通过。新增逐样本重建 clean 载波并与实际样本比对（用记录增益、task 参数和
   同一 `buildEnvelope`），容差 3 LSB，拒绝反相/改载波/改包络。对应审查用例
   “clean carrier must match the pinned synthesis algorithm even with updated hashes”。
5. **ramp 样本数舍入不一致**：Julia `round(Int, x)` 是 .5 取偶，JS `Math.round` 是 .5 向上；
   8500 Hz 下 `5×8500/1000 = 42.5`，Julia 取 42、TS 取 43，逐样本载波比对会在斜坡处偏差。
   新增 `roundHalfToEven` 并用于 `buildEnvelope`，与 Julia 对齐；另用 8500 Hz 任务端到端
   复核 `cwwave verify` 通过（`audio-carrier` 在 checks 中）。对应审查用例
   “ramp sample rounding matches Julia ties-to-even at 8500 Hz”。

修正后审查用例全部通过；`docs/evidence/P0-004-low-snr` 的 `-20 dB` 组合经
`cwwave verify` 通过（`measuredSnrDb=-20.0278`，退出码 0），最终 `npm test`/
`npm run test:built` 全部通过。本实现在 `tests/signal.test.ts` 也补了低 SNR 与
ties-to-even 回归用例。

## 7. 关键设计取舍与说明

- **同比例归一化导致 clean 幅度随 seed 变化**：增益由 noisy 峰值决定，因此不同 seed 下
  `clean.wav` 的绝对幅度不同；去掉该增益后的预归一化波形与 seed 无关（Julia 测试
  用 `clean/gain` 逐样本比较验证）。这是“保 SNR、不截幅”的直接结果。
- **seed 复现范围**：`seed` 固定 `TyCommunication.awgn` 的 `MT19937ar` 流。已记录环境下
  相同任务逐字节/逐样本复现；跨 Julia 或 TyCommunication 版本不作保证。
- **量化误差**：点长为 `1.2/wpm` 秒，样本边界用整数公式四舍五入，单边界误差
  ≤ 0.5 样本；`result.json` 记录时长误差与最大边界误差，`verify` 独立重算。
