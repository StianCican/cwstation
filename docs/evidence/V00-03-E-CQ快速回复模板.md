# V00-03-E CQ快速回复模板

2026-10-21。限定实现与复核完成。只在既有`ReplySessionImpl`、显式`--reply-prepared`模式增加严格CQ本地规则；未增加入口、服务、provider、依赖、持久化、发送循环或状态真源。

## 实现与主链

- 收报仍沿`cwrig receive → rig-receive → ReplySessionImpl → requestChatCompletion`。prepared模式收口后先检查完整正文；普通continuous/单轮路径不变。CQ不匹配时继续走同一continuous AI三字段schema。
- 本地命中语法为`CQ [限定词...] DE <配置peerCall> K`，仅归一连续/首尾ASCII空格，不做大小写或语义近似处理。限定词allowlist为`CQ/TEST/DX/QRP/QRO/NA/SA/EU/AF/AS/OC/POTA/SOTA/IOTA`，最多6个。完整模板为`<peerCall> DE <ownCall> K`，继续经过既有回复正文校验。
- 呼号不符、KN、尾随词、非法/未知token、超限限定词及非完整CQ正文均回退AI。`provider=disabled`仍不产生回复提案。本地命中事件用`replySource=local_cq_template`、`fastPathRule=cq_de_peer_k`、`modelWaitMs=0`标明来源；不再用`preparedCache`表示新语义。
- 发送仍沿`runCwTrial → CwTrialSession`。既有`EDIT`人工编辑、确认、最终正文复校验及单次模拟发送保留；本地生成提案不代表已发送。
- V00-03-D的AI整句候选schema/缓存语义已从当前prepared实现移除。03-D仍保留历史测试/集成证据；当前入口不兼容旧的`prepared`候选JSON schema。
