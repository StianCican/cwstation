## 主链与边界

原`cwrig receive → rig-receive → createReplySession/ReplySessionImpl → requestChatCompletion`原地扩展。显式`--reply-continuous`开启连续内存上下文，AI可选择严格JSON的reply/wait/end，旧单轮仍reply/no_reply；reply仍要求大写、合法字符、30字节以内及禁止^。历史标注真实接收与proposal NOT SENT，不把生成内容当成已发送，wait不轮询同一文本，end终止后续请求。新非空白撤销已展示提案并同步发invalidated，在途请求取消，未收完文本合并后等下一idle；旧flight不得晚到发布。

没有新增入口、服务、依赖、持久化格式/真源或第二HTTP/provider；实际CLI已调用此模式，不是候选helper。旧单轮与03-B保留，连续与03-B发送flag互斥；未决intent原阻断、真实E/TEST限制不变。本项没有连续发射，不删除/换目录绕过历史记录。

速度分离：idle默认2500ms（核心与CLI均1000..10000），连续模型预算默认5000ms（100..10000）；从boundary开始预算，使用单调时钟显示idleMs/modelMs/totalMs，超预算取消并在发布前再次检查实逝时间，防止事件循环先处理响应而迟到发布。WPM只为用户声明（5..60，默认20），不测对方实际码速、不设置电台；时长直接复用既有signal.encodeCwText/buildTimeline，合法但不在既有编码表中的字符显示null而不改变合法性。没有自制摩尔斯表。最多12次收口尝试、渲染历史至多12000字符，并为标签及有界回复预留空间；可能提前停止，不静默裁剪历史。单轮缓冲1024字符。idle是文本收口启发式，不是空口结束/载波空闲证明；默认idle加历史真实模型样本1.856秒仅约4.4秒示例，不是时延保证。
