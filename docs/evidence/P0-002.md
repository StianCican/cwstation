关键进程级用例（两种模式均通过）：

- `crash during execution is recovered as unknown and blocks further keying`：SIGKILL 后复用同一临时目录重启，陈旧锁/socket 被识别接管，遗留 running → unknown，后续 transmit 被 blocked。
- `long-lived connection does not block graceful SIGTERM shutdown`：保持从不发帧的长连接，SIGTERM 后 daemon 退出码 0 并打印 `daemon.stopped`。
- `second daemon on the same socket/database is refused`：第二实例退出码 1，原实例仍可 ping。

测试日志：测试期各 daemon 的 stdout/stderr 追加到工作区 `logs/daemon-<pid>.log`（匹配既有 `*.log` 忽略规则）。临时目录与数据库在各自用例结束后删除，不触碰用户数据。

## 5. 未决项与已知限制

- 仅 `FakeKeyer`，未接真实电台、未做真机验证；`doctor.fakeOnly` 恒为 true。
- `unknown` 结果的解除仍未实现：进入 `unknown` 后只能停止 daemon 并人工核查数据库；没有 `resolve-unknown` 命令。
- 内存态 `blockedReason` 在数据库不可写时无法持久化，仅本次进程内 fail closed；重启后是否仍 blocked 取决于是失败前是否有已落盘的 unknown/running 记录。
- mkdir guard 若恰在临界区内崩溃而残留，需人工删除该 guard 目录后 daemon 才能再启动（刻意的 fail-closed 取舍，避免误删活锁）。
- 状态改变抢占在途会判 `unknown`，因此会阻止后续发射直至人工核查；这是安全语义，不是缺陷。
- 仅支持 CW 单一模式与单一频点；`dev.state` 为测试钩子，默认关闭。

## 6. Codex 最终审查与验收（2026-10-05）

DSH 第二轮交付后，代码修改权交回 Codex。最终审查补上以下修正：

- `DaemonServer.dispatch` 在 closing 后拒绝新请求，包含停机前已建立的连接。
