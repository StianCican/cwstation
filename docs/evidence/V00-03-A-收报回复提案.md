## 用户可见增量与主链

```bash
node dist/apps/cwrig.js receive --decoder <multimon-ng> --pcm-s16le <file|-> \
  --reply-config <assistant-config-v1.json> \
  --own-call B1AA --peer-call B2BB [--reply-idle-ms 2500]
```

- 主链：`apps/cwrig.ts receive → apps/rig-receive.ts → packages/receive`（原 PCM/音频解码
  函数未改）`→ packages/assistant/reply.createReplySession → chat.requestChatCompletion
  → 现有 version1 配置/端点`。回复事件由同一 CLI 的 `print` 输出，GUI 以后直接调用
  `createReplySession`，不解析 CLI stdout。
- 三个回复参数必须同时给出；不给出时旧收报路径、输出和退出码保持不变，不会默认联网。
  `--reply-idle-ms` 只能和回复参数一起用，范围 1000..10000，默认 2500。
- `--own-call`/`--peer-call` 各 2..12 位大写 ASCII 字母、数字或斜线，至少一个字母和
  一个数字，且不能相同；不猜测身份。
- 单会话最多一个 turn、最多一次模型调用。最后一个非空白字符后 idle，或正常 PCM EOF
  （`finish()`）收口；空格保留在 `receivedText`，缓冲上限 1024 字符，超限失败且不调用
  模型。idle 是应用层启发式，不是空口报文完成证明；不把 K/AR 当 prosign 解析。
- 模型在途时出现新非空白文本：撤销 turn、abort 请求、抑制迟到结果，不重试；提案发布
  后出现新非空白文本：发出 `type:"invalidated"`，不再有当前有效提案，不发起第二轮。
- 采集/解码失败或用户取消不是 EOF：CLI 取消会话、清 timer/模型，不发布迟到提案；
  正常 PCM 完成才 `finish()` 并等待有界结果。实时音频的 idle 在输入继续时触发，音频
  结束本身不冒充 PCM EOF。
- JSONL 事件固定为 `utterance`/`reply`/`invalidated`，全部带 `sessionId`、`turnId`、
  `revision`、`advisoryOnly:true`、`readOnly:true`。`reply` 含 `provider`、`model`、
  `validated`、`action`、`text`、`reason`、`errorCode`；不含原始模型文本、凭据、执行帧、
  批准或发射接口。
- 模型必须返回严格 JSON `{"action":"reply"|"no_reply","text":string,"reason":string}`；
  拒绝额外字段、代码围栏、非 JSON。`reply` 文本必须已是大写 ASCII、非空、≤30 字节、
  不含 `^`，并直接复用 `planCivCwMessage` 纯校验器；不截断、不替换、不规范化。
  `no_reply` 的 `text` 必须为空。`reason` 最多 300 字符且拒绝控制字符。
- `disabled` 明确 no_reply 且不联网；`mock` 本地确定性生成 `B1AA DE B2BB K` 一类合法
  短回复，事件明确 `provider:"mock"`，不冒充真实模型。

## 设计与首链检查（合并）

- 缺口→调用位置：回复会话由 `apps/rig-receive.ts` 的 `onChunk` 实际 `push`，PCM 成功
  后实际 `finish`；不是只新增模块。模型调用只发生在 `beginBoundary` 后一次。
- 复用：配置/传输来自既有 assistant version1；文本来自既有 `MultimonRxChunk`；回复
  校验来自 `planCivCwMessage`。解释与回复共用同一 HTTP 实现。
- 生命周期：`push` 同步，模型异步经 `onEvent`；`finish` 才等待本轮结果；`cancel` 清
  timer、abort、移除 signal listener，迟到结果因 `closed` 被抑制；无未处理模型 Promise。
- 输出语义：提案只读、`advisoryOnly:true`；没有批准/发送/帧字段；没有设备 transport。
- 入口/进程/协议/记录：仍一个 `cwrig receive` 入口、同一解码进程数量、同一 JSONL
  stdout（新增事件类型但不新增持久化格式）；无新服务或协议种类。
