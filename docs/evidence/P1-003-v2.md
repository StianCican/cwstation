# P1-003 v2：Windows 受保护管道桥接

日期：2026-10-06。范围：Windows原生与Linux离线Fake控制；未接USB或发射。

## 实现与边界

`native/windows/CwPipeBridge.cs`通过CreateNamedPipeW创建时应用protected DACL：
NETWORK全拒绝、当前token用户/SYSTEM全允许，顺序为deny→allow；每个实例
设置PIPE_REJECT_REMOTE_CLIENTS，首次实例FIRST_PIPE_INSTANCE。使用
RawSecurityDescriptor逐项验证owner、保护标志、ACE数量/类型/权限/主体/顺序。
每次接入先建立下一个监听实例，保持管道名生命期；创建或接受失败立即关闭。

客户端同一HANDLE核对服务token用户和实际ACL，通过后才发送RPC。Windows
daemon/CLI通过helper的匿名stdio转发，`bridge.ts`映射Duplex流，复用原有
NDJSON及RPC处理，不修改核心、schema4、协议1或配置版本。Linux不启动helper。
桥接丢失停止接单并走撤销批准、有界取消、关闭数据库和释放锁；helper监测
父进程退出及stdin EOF，正常停机有实际管道写入ack后关闭。

重叠I/O允许双向读写。32连接、16块默认写队列（每块64KiB）、128KiB内部帧、
Node发送队列512KiB；超过读高水位关闭该连接。实际写入/stdout等待超过5s
退出helper并触发daemon关闭，Node等待写ack超过6s亦fail closed。
运行时不编译、不接受默认DACL旁路或任意helper路径覆盖。

## 协作与修正

DSH产出首版C#与构建脚本，但未完成TS接入或有效验收；多次headless已停止并
交接。Codex收回全部修改权，完成严格ACL、deny顺序、AccessCheck具体权限位、
有界输入输出、去除测试安全旁路、重叠I/O和写ack，以及TS接入和测试。
最初同步I/O造成RPC超时，已修正。初次完整Windows回归出现一项既有维护测试
失败（覆盖备份的退出码1而非4），独立重跑及之后全套通过，未改维护实现。
超大帧测试发现helper关闭但退出码0，已改为明确失败退出。
收尾将核心恢复放入transport-ready回调，连接在恢复完成前只缓冲不派发。
一次后续回归暴露旧并发测试400ms Fake窗口不足，改为已有连接发busy/abort，
Fake窗口5s、超时10s；仍断言busy与cancelled，未放宽控制业务行为。

## 原生观测

`node.exe logs/native-smoke.mjs`：Node24.16.0。实际DACL：

```text
D:P(D;;FA;;;NU)(A;;FA;;;S-1-5-21-315597596-3625026891-1088859758-1001)(A;;FA;;;SY)
```

SID来自实际token，不在实现硬编码。AccessCheck当前token granted=true、
error=0；禁用用户SID的受限token allowed=false、error=0，拒绝成立。
这不等于已真实登录第二用户或从远程访问；NETWORK deny为结构核验，
远程拒绝标志在创建时设置，没有声称已做远程登录测试。

## 限制与后续

同用户任意shell、SYSTEM和管理员提权不在对抗范围，不能证明真人批准。
真实第二用户、远程登录、helper启动挂起和持续写阻塞的专门故障注入未覆盖；
实现具备有界处理，但不能宣称这些场景都已实测。多种Windows系统及无开发
工具的干净机器尚未验收；.NET Framework4.x和Windows运行时需要随发布目标
检查。产物构建含编译时间差异，hash用于当次产物校验，不保证字节重复。

USB只读接入仍需固定串口库、IC-7300设置及开口控制线行为，不能因本轮通过
就打开串口或发射。Windows成品安装/便携包仍未制作。
