## 实现摘要

- `packages/core/src/tx-controller.ts`：`ControllerOptions` 新增可选同步 `approvalGuard?: (proposal: Readonly<Proposal>) => void`。
  `approve` 在查得 proposal 后、返回 existing 或写批准前调用；`transmit` 在已有终态幂等查询之后、消费批准/写 intent 之前调用。
  未配置时 `this.approvalGuard?.(...)` 为空操作，默认行为与旧版本一致。回调抛出（含 `ControllerError("blocked")`）不会写批准、不会写 intent，也不会被当成 unknown；`approve` 仍是同步 API。沿用 `setState` 与 `invalidate(reason,true)`，未新增 force 状态 API，未扩大 `StationMode`，未改线协议/DB schema。
- `packages/rig-status/src/approval-gate.ts`（新增）：
  - `ReadOnlyRigApprovalGate` 持有 `TxController` 与显式 `RigStatusEndpoint`，只经由 `RigStatusClient` 的 `watch` 读取，不调用 `reconnect`、不打开串口。公开 `start/refresh/close/checkApproval/view`；后台 1 秒轮询，连接/请求均 2 秒期限；并发 `refresh` 合并为同一 promise，不排无限队列；`close` 递增 epoch 并断开 IPC，晚到结果被丢弃、绝不重建连接。
  - 断线后的有界“重连”仅指重新连接公开只读 IPC 以取得新服务状态，由下一次轮询（≤1 秒）触发；**不是设备串口重连，也不是设备服务自动重启**。
  - 运行时校验：`source=rig-statusd`、`readOnly=true`、`status/stale/simulation` 类型与合法 phase、`owner.protocolVersion=1`、非空且有界 `serviceInstanceId`、safe nonnegative `connectionGeneration`、`capabilities` 全字段实际类型与固定只读声明（`cwSend/cwStop/ptt=false`、`completionEvidence/stopEvidence="unavailable"`）、`snapshot` 的 `frequencyHz/mode/filter/snapshotTime`。旧服务无 owner、非法响应、快照过期 >2 秒或未来 >20ms 均拒绝批准并映射失联。未知设备模式保留在设备字段，核心 mode 仍为契约 CW，绝不把 USB 等映射成观测到的 CW。
  - 指纹含 `serviceInstanceId`、`connectionGeneration`、`frequencyHz`、真实 mode、filter、phase/stale/simulation 与能力，不含 `pollCount`/采样时刻。频率变化经 `setState` 持久化核心频率；真实 mode≠CW 时 `backendConnected=false`，核心 mode 仍为 CW。ready、新鲜且 mode=CW 时 `backendConnected=true`（仅表示可用于 CW 上下文，不授予写能力）。任意新指纹含初次/恢复，若 `setState` 未提升 generation 则调用 `invalidate(reason,true)`；相同指纹更新缓存采样时间，不提升 generation，不恢复旧批准。IPC 故障/过期映射 `backendConnected=false` 并撤销；同一故障已处于失联映射时不重复刷代次。
  - `checkApproval` 要求报告新鲜且 ready、真实 mode=CW、频率匹配 proposal，随后用既有 `planCivCwMessage` 复核提案文本（不复制字符表），最终**固定**抛出 `ControllerError("blocked")`：只读设备永不授予 send，`simulation=true` 也不授予。
  - 设备上下文持久化失败时清空可批准缓存，保留核心故障闩锁；后台路径不产生未处理拒绝。
  - `ReadOnlyRejectingKeyer` 实现既有 `Keyer` 契约，`keyedCount` 恒为 0，`transmit` 拒绝且不接触设备；不能在真实设备路径上配置 `FakeKeyer` 把批准变成模拟执行。
- `packages/daemon/src/server.ts`（可选设备钩子）：新增可选 `beforeDeviceCommand?: () => Promise<void>` 与 `deviceStatus?: () => unknown`。
  前者在 `propose/approve/transmit` 前 `await` 设备刷新，使用单调时钟及请求取消状态；hook失败、超期、已响应/连接销毁、stopAccepted或closing时拒绝后续操作，核心仍同步复核缓存状态。后者使 `status/doctor` 附带只读设备视图；未提供时不增加任何字段。
- `apps/daemon.ts`（显式接入）：新增仅 CLI 参数 `--rig-endpoint <path|pipe>`，用既有 `parseRigStatusEndpoint` 校验；默认 daemon 仍为 Fake。带该参数时使用 `ReadOnlyRejectingKeyer`、`loadState(...,{backendConnected:false})` 并安装 `approvalGuard`；`fakeOnly=false` 且禁用 `dev.state`（避免伪造状态或错误宣称 Fake 解除 unknown）。`controller.recoverOnStartup()` 在 `onTransportReady` 完成后于 `server.start()` 之后 `start` gate。关闭/启动失败时先 `close` gate（只断开 IPC，不关闭独立设备持有者），再关闭核心/journal。不启动设备服务，不争用 COM17。

## 静态自查场景（限定实现层，非运行验收）

| 场景 | 静态结论 |
|---|---|
| 状态改变撤销批准 | 身份/代次/真实模式/可用/能力变化在未提升 generation 时显式 `invalidate(reason,true)`；频率变化由 `setState` 撤销 |
| 同频服务重启 | `serviceInstanceId` 变化进入指纹且属身份变化；同频下 generation 未提升则 `invalidate`，旧批准不被恢复 |
| 非法/过期报告 | `parseDeviceContext` 拒绝无 owner、类型/能力/频率/滤波/时间非法；>2s 过期或 >20ms 未来均拒绝并映射失联 |
| 并发 refresh 与 close | `refreshPromise` 合并请求；`close` 置 `closed`、递增 epoch、清 timer、断 IPC，晚到结果按 epoch 丢弃 |
| 批准幂等 | `approve` guard 在返回 existing 前调用；`transmit` guard 在终态幂等查询之后，重复请求不重新键控 |
| 执行前再检 | `transmit` guard 在消费批准/写 intent 之前同步复核；`ReadOnlyRejectingKeyer` 为最后保险 |
| 核心持久化失败 | `applyContext/applyFailure` 捕获 `setState/invalidate` 异常，清空可批准缓存，保留核心故障闩锁 |
| RPC 超时晚到 | `beforeDeviceCommand` 使用单调时钟、responded/socket.destroyed、stopAccepted/closing拒绝迟到操作；端到端未验证 |
| 默认 Fake 兼容 | 未提供 `--rig-endpoint` 时无 guard、无设备 hook、`fakeOnly=true`、仅 FakeKeyer，行为不变 |
