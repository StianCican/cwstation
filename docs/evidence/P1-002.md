## Windows 命名管道权限证据

Codex 对实际 Windows Fake daemon 的临时管道 `cwstation-acl-review-R1jVg1` 执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/windows-pipe-acl.ps1 -PipeName cwstation-acl-review-R1jVg1
```

READ_CONTROL查询得到DACL（用户SID以OWNER表示，原值是本机普通用户SID，不是密钥）：

```text
D:(A;;FA;;;SY)(A;;FA;;;BA)(A;;FA;;;OWNER)(A;;FR;;;WD)(A;;FR;;;AN)
```

SYSTEM/Administrators/owner完整权限；Everyone/Anonymous读权限。后两者的读权限不等于已证明可发送命令，本次没有用另一Windows用户或远程主机做实际攻击测试；亦不能证明仅本用户可连接。默认管道名带用户标识不是授权机制。doctor使用`default-dacl-not-runtime-verified`，不将开发机实测泛化为每次运行已验ACL。

最小后续建议：评估将命名管道DACL限制为当前用户与SYSTEM、验证远程连接限制及创建/连接竞争；可复用成熟原生绑定或小型Windows适配。不在本任务自行建设权限平台或替换成公开TCP。权限方案需完成设计与验证后才能验收Windows真实控制。

同一临时daemon通过原生CLI `stop` 返回accepted，随后输出`daemon.stopped`并exit0；ACL探测不发送任何控制payload。本轮测试/探测daemon及headless已退出，用户web/Syslab不受影响。
