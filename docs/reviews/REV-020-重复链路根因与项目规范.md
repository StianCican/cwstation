# REV-020 重复链路根因与项目规范

日期：2026-10-20。作者/静态复核：Codex。用户要求：接续项目，保持一条主轴，分析为何反复造链路并落实项目规范。本报告是Codex的事实核查与流程修正，不是DSH独立审议或运行行为验收。

## 结论与责任

问题不在于缺少设计、测试或审议，而在于这些流程主要约束各项实现内部的正确性，未充分约束实现之间的替代关系。每次都能说明局部新增的理由，却没有要求同轮回答“主链因此改善什么、旧调用者何时切换”。结果是统一入口之下仍保留并扩展不同实现，候选逐渐积累成新的维护路径。

Codex负责路线、任务拆分和验收，未及时限制这种累积，这是规划和审查责任。不能把问题简单归因于用户逐次授权、DSH执行或会话切换。现有记录能证明文档和调用关系的缺口，不能证明某次模型实际遗漏了哪段上下文，也不能仅凭路径数量断言已发生串口争用或性能故障。

## 可定位的原因

| S2：新增候选与迁移脱节 | P2-013第1节明确独立实现候选仲裁且不替换生产；REV-019记录两个候选未在生产实例化，既有只读和试验仍用各自会话 | 离线隔离本有合理边界，但缺少接入或冻结的明确阶段出口 |
| S2：把统一入口进展当成内部收敛进展 | ADR-019沿用rig.sh/rig-launch/rig-controld，同时另fork交互端；旧试验迁移列为后续。rig.sh现仍明确分支到单次试验和冻结IPC实验 | 命令看似统一，但所有权、状态与记录实现仍分开，外壳复用不足以证明链路合并 |

| S2：审议缺少跨任务收敛标准 | 原规范R01-R12覆盖契约、授权、持久化、失败处理和证据，没有要求列入口/进程/协议/格式增减及替代验收 | 新实现可独立通过测试，旧实现不迁移也不妨碍本项交付，局部通过累积为整体分叉 |

MEMORY约96KB，既有当前决定，也保留大量历史“下一步”；README还同时保留真实证据和“未接触真实电台”的旧限制。这是上下文歧义的证据，不是单凭文件长度判定工具失效。Git记录也显示先建立统一Fake切片（e08c829），再收敛回既有单次会话（2fcfd33）；变化有授权记录，但此前未将避免反复切换落实成任务门槛。

## 本轮落实

采用现有AGENTS作为执行入口、ADR-020作为主链决策、MEMORY顶部作为现状，不建立第二套平台或状态数据库。

1. AGENTS固定现有单次试验调用路径，列明冻结对象、任务六项要求、替代验收与偏离讨论条件；修正阶段和Git入口。
2. MEMORY标明当前规则和历史边界，历史要求与证据保留，旧“下一步”不自动成为任务。
3. ADR-019与P2-016就地标注被ADR-020替代的范围，README说明历史入口地位并纠正过期限制。
4. 既有审议规范增加R13：检查主链位置、复用、复杂度增减与迁移事实。既有安全/停止/unknown约束继续适用。

主链保持：rig.sh --cw-trial → rig-controld --cw-trial → runCwTrial → CwTrialSession → 注入的模拟/既有受限串口transport。默认只读监视保留。当前主链是单次试验，尚无可靠真实完成/停止证明，也不是日常连续操作系统。本轮不擅自选择下一项功能，更不重开统一平台设计。
