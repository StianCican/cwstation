# CW Station 起步路线

目标：先建立可恢复的确定性控制闭环，再接入真实设备、解码器和 AI 策略。

## 当前优先级（2026-10-20，用户明确要求）

尽量小的闭环，之后再逐步添加功能。先复用既有实现，确定单设备的一条主操作流程，再逐步替换重复链路；不再以完整平台建设作为当前可用成果的前置条件。

下一闭环候选为“显示上下文 → 人工确认 → 一次固定短报文 → 停止请求/查询 → 退出释放”，先离线验证，真实操作另行授权。先比较复用现有CW试验会话与新Fake服务适配的最小改动，再确定实现；尚未授权大规模重构或删除旧记录。必要的批准、单持有者、不重发、未知状态阻断和修改前保护必须保留。

通用生产账本/历史导入、自动重连、新工具平台、多设备、AI及成品打包不作为当前必做项；已有能力可保留，新增工作由实际闭环需要驱动。下方长期阶段和2026-10-15计划属于历史路线，不自动作为当前执行清单。核查见 `reviews/REV-019-最小闭环与复杂度核查.md`，持续要求见MEMORY.md顶部。

## 分发目标（2026-10-06 用户确认）

以 Windows 成品为主，交给同学和学弟使用；Linux 支持继续保留。
使用者无需开发环境即可启动，具有日常操作界面、首次设备配置、独立个人数据
及诊断导出。发布须在无开发工具的 Windows 环境验收，要求见
`docs/design/windows-distribution-requirements.md`。

最小操作界面和打包验证应在首次成品分发前完成，不能等到 Phase 3 的 AI
策略阶段才开始。Phase 0/1 期间可继续以 CLI 验证核心；安装包或便携包、
界面技术和支持系统范围尚待选型。本次只确认交付目标，不授权真实发射。

## Phase 0：离线核心闭环

范围：TypeScript/Node.js 守护进程，FakeRig、FakeKeyer、SQLite、CLI；不接电台、不发射、不接 AI。

交付：

- 版本化命令、事件和结果契约。
- 提案创建、人工批准、过期、撤销和拒绝。
- 单一发射执行器：同一时间最多一个发射任务。
- FakeKeyer 的完成、取消、超时、迟到回执和结果未知状态。
- 频率/模式变化、进程重启、后端断连后自动撤销授权。
- SQLite 日志、审计记录和第一版数据库迁移。
- `cwctl doctor`、`cwctl status`、`cwctl propose`、`cwctl approve`、`cwctl abort`、`cwctl audit`。
- Julia/MWORKS 离线工具：CW 波形合成、噪声场景和回放输入；通过任务文件或本地进程协议调用，不参与发射控制。

验收：用 Fake 后端完成“提案 → 批准 → 执行 → 完成/取消/结果未知 → 审计”的完整流程；故障注入后不能产生第二次未经批准的发射。

## Phase 1：接入单一真实设备路线

先确定一台电台、一种键控方式和设备唯一持有者。先假负载，再有人在场的日常 CW。

验收：确认取消、断连、USB 拔插、休眠、进程退出和恢复行为；未完成急停与恢复验证前，不开放自动 CQ。

## Phase 2：日志与抄收辅助

- WAPC-CW 中国参赛台和日常 CW。
- WAPC 接收同时支持省码和国外流水号。
- SQLite 作为日志真源，TLF/N1MM 作为导入、导出或可选对账工具。
- 一个解码器只提供抄收建议，人工确认呼号和交换。
- 逐 QSO、重复、系数、计分和 Cabrillo/ADIF 字段对账。

## Phase 3：操作界面与策略

在首次分发所需的最小操作界面基础上完善工作流，复用与 CLI 相同的守护进程接口。本地 Web 为当前建议，技术尚待选型。先加入有限 CQ 循环和可撤销策略，再评估 AI 建议。策略不能绕过确定性授权、互锁和急停。

## Phase 4：扩展

在第二个比赛、第二种设备或第二种模式出现真实需求后，再验证规则、适配器和模式接口。FT8、RTTY、更多解码器及多智能体不提前进入 Phase 0。

## 历史起步顺序（2026-10-05）

1. 固定 TypeScript/Node.js 工程和目录边界。
2. 定义 `Proposal`、`Approval`、`TxRequest`、`TxOutcome`、`StationState`、`AuditEvent` 契约。
3. 写确定性发射状态机和 FakeKeyer。
4. 写 SQLite journal 与迁移入口。
5. 写 CLI 最小闭环和故障注入场景。
6. 写 Julia CW 合成/回放工具及版本化任务格式。
7. 通过离线验收后，再决定真实设备路线。

## 明确不提前做

- 不先做 AI 自主发射。
- 不先做多设备并行和透明 CAT 代理。
- 不先迁移现有深度学习解码器。
- 不以“行数少”作为项目预算或可靠性证明。
